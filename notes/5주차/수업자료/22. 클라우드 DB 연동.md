## Day 2 복습: 왜 `db`로 접속했을까?

Day 2의 연결 문자열은 이런 형태였습니다.

```
DATABASE_URL=mysql+pymysql://todo_user:todo_pass@db:3306/todo_db
```

여기서 `db`는 Docker Compose 안의 service 이름입니다.

```yaml
services:
db:
image: mysql:8.0

web:
environment:
DATABASE_URL: mysql+pymysql://todo_user:todo_pass@db:3306/todo_db
```

Compose는 자동으로 네트워크를 만들고, 그 안에서 service 이름을 hostname처럼 사용할 수 있게 해줍니다. 그래서 `web` 컨테이너는 `db:3306`으로 MySQL 컨테이너에 접속할 수 있었습니다.

오늘은 이 `db` 자리에 RDS endpoint가 들어갑니다.

---

## RDS 연결에 필요한 6가지 값

!day4-04-rds-connection-card.png

RDS 연결에 필요한 6가지 값

| 값 | 의미 | 예시 |
| --- | --- | --- |
| endpoint | RDS 접속 주소 | `ktc-day4-demo.xxxxxx.ap-northeast-2.rds.amazonaws.com` |
| port | MySQL 접속 포트 | `3306` |
| database name | 내가 사용할 DB 이름 | `ktc_001_db` |
| username | DB 사용자 | `ktc_001` |
| password | DB 비밀번호 | 제공된 임시 비밀번호 |
| security group | 누가 DB에 접속할 수 있는지 정하는 방화벽 | 3306 허용 규칙 |

RDS 연결 문자열 예시:

```
DATABASE_URL=mysql+pymysql://ktc_001:<password>@<rds-endpoint>:3306/ktc_001_db
```

!day4-03-database-url-breakdown.png

DATABASE_URL 구성 요소 해부도

주의:

- `<password>`와 `<rds-endpoint>`는 본인에게 제공된 값으로 바꿔야 합니다.
- 비밀번호가 들어간 `DATABASE_URL`을 GitHub에 올리면 안 됩니다.
- 공백이 들어가면 연결이 실패할 수 있습니다.

## 실습 2. RDS 연결 문자열로 바꾸기

먼저 `.env.example`을 `.env`로 복사합니다.

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

macOS/Linux:

```bash
cp .env.example .env
```

그다음 `.env`에서 `DATABASE_URL`을 찾습니다.

기존 값:

```
DATABASE_URL=mysql+pymysql://todo_user:todo_pass@db:3306/todo_db
```

RDS 값으로 변경:

```
DATABASE_URL=mysql+pymysql://ktc_001:<password>@<rds-endpoint>:3306/ktc_001_db
```

확인할 부분:

- `ktc_001`은 본인 계정으로 바꿨는가?
- `<password>`는 본인 비밀번호로 바꿨는가?
- `<rds-endpoint>`를 정확히 복사했는가?
- 마지막 DB 이름이 본인 DB 이름인가?
- `:3306`이 빠지지 않았는가?

## 실습 5. MySQL client 컨테이너로 RDS 접속

RDS는 내 로컬 Docker Compose의 `todo-db` 컨테이너가 아닙니다. 그래서 `docker exec todo-db`로 들어가는 방식이 아니라, MySQL client가 들어있는 컨테이너를 잠깐 실행해 RDS에 접속합니다.

!day4-07-mysql-client-container.png

MySQL client 컨테이너로 RDS 접속

Windows PowerShell에서는 한 줄로 실행하는 것이 가장 덜 헷갈립니다.

```powershell
docker run --rm -it mysql:8.0 mysql -h <rds-endpoint> -P 3306 -u ktc_001 -p ktc_001_db
```

macOS/Linux에서는 여러 줄로 나눠 실행해도 됩니다.

```bash
docker run --rm -it mysql:8.0 mysql \
  -h <rds-endpoint> \
  -P 3306 \
  -u ktc_001 \
  -p \
  ktc_001_db
```

비밀번호 입력창이 나오면 본인 비밀번호를 입력합니다.

MySQL shell에서 확인합니다.

```sql
SELECT DATABASE();
SELECT CURRENT_USER();
SHOW TABLES;
SELECT * FROM todos;
SELECT COUNT(*) AS todo_count FROM todos;
EXIT;
```

성공하면 다음을 확인할 수 있습니다.

- 현재 접속한 DB 이름
- 현재 접속한 DB user
- todo 테이블 목록
- FastAPI 앱에서 생성한 todo 데이터

```sql
SELECT student_id, nickname, db_user, created_at
FROM classroom.checkins
ORDER BY created_at DESC
LIMIT 20;
```

## 자주 만나는 에러

!day4-05-security-group-gate.png

RDS 보안 그룹 3306 허용 여부 비교

| 에러 | 가장 흔한 원인 | 먼저 확인할 것 |
| --- | --- | --- |
| `connection timed out` | RDS 보안 그룹에서 3306이 열려 있지 않음 | 상태 확인 |
| `Access denied` | username/password 오류 | 본인 계정과 비밀번호 확인 |
| `Unknown database` | DB 이름 오타 | `ktc_001_db` 같은 본인 DB 이름 확인 |
| `Unknown MySQL server host` | endpoint 오타 | RDS endpoint 다시 복사 |
| 앱은 뜨지만 데이터 저장 실패 | 테이블이 아직 없음 | 로그 확인,  테이블 생성 방식 확인 |
| 계속 로컬 DB에 저장됨 | `DATABASE_URL` 변경이 적용되지 않음 | 컨테이너 재실행, compose 설정 확인 |
| `mysql` 명령어가 없음 | web 컨테이너에는 MySQL CLI가 없음 | `docker run --rm -it mysql:8.0 mysql ...` 사용 |

## 핵심 정리

오늘 바뀐 것은 코드 전체가 아니라 DB 연결 대상입니다.

| 구분 | Day 2 | Day 4 |
| --- | --- | --- |
| DB 위치 | 로컬 MySQL 컨테이너 | AWS RDS MySQL |
| DB 주소 | `db` | RDS endpoint |
| 확인 방법 | `docker exec todo-db` | MySQL client 컨테이너 |
| 접근 제어 | Compose network | RDS security group + DB user |
| 운영 관점 | 개발 환경 | 클라우드 운영 환경에 가까움 |

가장 중요한 한 줄:

> 애플리케이션은 환경변수만 바꿔도 다른 DB에 연결할 수 있고, 운영 환경에서는 그 연결을 계정과 네트워크로 통제한다.
