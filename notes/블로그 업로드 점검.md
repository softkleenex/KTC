# KTC 노트 블로그 업로드 점검

## 업로드 전 전체 기준

- 강의자료 원문을 그대로 옮기기보다, 개인이 이해한 흐름과 실습 과정 중심으로 재작성한다.
- `![[...]]`, `attachment:...`, `!image.png` 같은 Obsidian 전용 링크는 블로그 플랫폼에 맞는 이미지/링크 형식으로 바꾼다.
- PDF 강의자료는 블로그 본문에 직접 복붙하지 않고, 필요한 경우 요약과 출처 메모로만 활용한다.
- `.env`, RDS endpoint, password, token, 개인 식별 정보는 절대 포함하지 않는다.
- 코드블록에는 언어 태그를 붙인다. 예: `python`, `tsx`, `bash`, `sql`, `yaml`.

## 주차별 블로그화 우선순위

| 우선순위 | 범위 | 이유 |
| --- | --- | --- |
| 1 | 4주차, 5주차 | Day별 본문형 정리가 완료되어 블로그 초안으로 쓰기 좋음 |
| 2 | 학습일지 | 회고와 "내가 이해한 방식"이 이미 정리되어 있음 |
| 3 | 1~3주차 Day 노트 | 내용은 풍부하지만 이미지 링크와 메모체 정리가 필요 |
| 4 | 강의자료 폴더 | 원문 성격이 강해 블로그 본문보다는 참고자료로 활용 |

1. `Next.js App Router를 처음 잡을 때 이해해야 할 것`

## 남은 정리 포인트

- 1~3주차의 `Pasted image ...` 링크는 실제 이미지 파일이 없으면 블로그에서 깨진다.
- 1~3주차 일부 문장은 실시간 메모체라 문장형 설명으로 다듬으면 좋다.
- 강의자료 Markdown 안의 `attachment:` 링크는 블로그에 직접 올릴 때 제거하거나 이미지 파일을 별도로 정리해야 한다.
- PDF 파일은 용량이 커서 블로그 저장소와 분리할지 결정이 필요하다.
