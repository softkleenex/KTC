## 01. 왜 Docker를 쓰는가

개발을 하다 보면 “내 컴퓨터에서는 잘 되는데 다른 사람 컴퓨터에서는 안 된다”는 문제가 자주 나온다. 운영체제 버전, 라이브러리 버전, 설치 순서, 환경변수 차이처럼 작은 차이가 실행 오류를 만든다.

Docker는 애플리케이션과 실행에 필요한 환경을 이미지로 묶고, 그 이미지를 컨테이너로 실행하게 해준다. 즉, 실행 환경 자체를 코드처럼 다룰 수 있게 해주는 도구다.

```text
애플리케이션 코드
  + 런타임
  + 라이브러리
  + 환경 설정
  = Docker Image

Docker Image 실행
  = Docker Container
```

---

## 02. 베어메탈, VM, 컨테이너

서버 운영 방식은 크게 베어메탈, 가상머신, 컨테이너 흐름으로 발전했다.

| 구분 | 설명 | 특징 |
| --- | --- | --- |
| Bare Metal | 물리 서버에 OS를 직접 설치 | 성능은 좋지만 자원 분리가 어려움 |
| Virtual Machine | Hypervisor 위에 여러 Guest OS 실행 | 격리 수준은 높지만 무겁고 느림 |
| Container | Host OS 커널을 공유하며 실행 환경만 격리 | 가볍고 빠르며 배포가 쉬움 |

컨테이너는 VM처럼 독립된 서버처럼 보이지만, 실제로는 Host OS 커널을 공유한다. OS 전체를 복제하지 않기 때문에 이미지 크기가 작고 부팅이 빠르다.

---

## 03. 컨테이너를 가능하게 하는 리눅스 기능

컨테이너는 마법이 아니라 리눅스 커널 기능을 조합한 결과다.

| 기술 | 역할 |
| --- | --- |
| `chroot` | 특정 디렉토리를 루트처럼 보이게 하여 파일 시스템 격리 |
| `namespace` | PID, 네트워크, 호스트명 등 시스템 리소스의 이름공간 격리 |
| `cgroup` | CPU, 메모리, 디스크 I/O 같은 자원 사용량 제한 |

`namespace`가 “서로 보이지 않게 만드는 기능”이라면, `cgroup`은 “얼마나 쓸 수 있는지 제한하는 기능”이다. 이 둘 덕분에 하나의 컨테이너가 폭주해도 호스트 전체에 미치는 영향을 줄일 수 있다.

## 04. Docker 구성 요소

Docker는 클라이언트-서버 구조로 동작한다.

| 구성 요소 | 역할 |
| --- | --- |
| Docker Client | 사용자가 터미널에서 입력한 명령을 Docker daemon에 전달 |
| Docker Host | Docker daemon이 실제로 이미지, 컨테이너, 네트워크를 관리하는 환경 |
| Docker daemon | 컨테이너 생성, 실행, 삭제 등 실제 작업 수행 |
| Image | 컨테이너 실행을 위한 읽기 전용 템플릿 |
| Container | 이미지를 실행한 실제 프로세스 상태 |
| Registry | Docker Hub처럼 이미지를 저장하고 내려받는 저장소 |

정리하면 이미지는 설계도, 컨테이너는 그 설계도로 실제 실행한 인스턴스다.

## 05. Docker 기본 명령어

### 이미지 빌드

```bash
docker build -t my-app .
```

현재 디렉토리의 Dockerfile을 읽어 `my-app`이라는 이미지를 만든다.

### 컨테이너 실행

```bash
docker run -it --name my-ubuntu ubuntu:20.04 bash
```

Ubuntu 이미지를 기반으로 새 컨테이너를 만들고, 터미널로 접속한다.

```bash
docker run -d --name web-server -p 8080:80 nginx
```

nginx 컨테이너를 백그라운드로 실행하고, 호스트의 8080 포트를 컨테이너의 80 포트에 연결한다.

### 실행 중인 컨테이너 확인

```bash
docker ps
docker ps -a
```

`docker ps`는 실행 중인 컨테이너만 보여주고, `docker ps -a`는 종료된 컨테이너까지 모두 보여준다.

### 실행 중인 컨테이너 내부 명령 실행

```bash
docker exec -it web-server bash
```

`run`은 새 컨테이너를 만들어 실행하는 명령이고, `exec`는 이미 실행 중인 컨테이너 안에서 명령을 실행하는 명령이다.

## 06. 포트 매핑

컨테이너 안에서 서버가 떠 있어도 호스트와 연결하지 않으면 브라우저에서 접근할 수 없다.

```bash
docker run -d nginx
```

위 명령만으로는 nginx가 컨테이너 내부 80 포트에서 실행될 뿐, 내 컴퓨터의 포트와 연결되지 않는다.

```bash
docker run -d -p 8080:80 nginx
```

`-p 8080:80`은 다음 의미다.

```text
localhost:8080
  → 컨테이너 내부 80번 포트
```

---

## 오늘의 정리

- Docker는 실행 환경 차이를 줄이기 위해 애플리케이션과 환경을 함께 패키징한다.
- 컨테이너는 Host OS 커널을 공유하므로 VM보다 가볍고 빠르다.
- 이미지는 실행 템플릿이고, 컨테이너는 이미지를 실행한 상태다.
- `docker run`은 새 컨테이너 실행, `docker exec`는 실행 중인 컨테이너 내부 명령 실행이다.
- 외부에서 컨테이너 서비스에 접근하려면 포트 매핑이 필요하다.
